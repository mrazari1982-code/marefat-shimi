# راهنمای پشتیبان‌گیری و بازیابی سامانه معرفت

## زمان‌های اجباری پشتیبان‌گیری

1. پیش از واردسازی گروهی دانش‌آموزان یا کلاس‌ها
2. پیش از اجرای هر مهاجرت دیتابیس در production
3. پیش از اولین آزمون واقعی مدرسه
4. پس از پایان هر دوره آزمون مهم

## اجزای پشتیبان

- دیتابیس production شامل schema، توابع، سیاست‌ها و داده‌ها
- مخزن GitHub و شاخه `main`
- تنظیمات انتشار Cloudflare
- فایل اصلی داده ورودی مدرسه و گزارش اعتبارسنجی آن

## کنترل پیش از تغییر

- شمارش دانش‌آموزان، کلاس‌ها، آزمون‌ها، تلاش‌ها و پاسخ‌ها ثبت شود.
- شناسه آخرین مهاجرت ثبت شود.
- فایل ورودی بدون تغییر نگهداری و یک نسخه پاک‌سازی‌شده جدا ساخته شود.
- داده جدید ابتدا در staging یا پیش‌نمایش واردسازی بررسی شود.

## ترتیب بازیابی

1. انتشار frontend به آخرین commit سالم برگردد.
2. در صورت تغییر schema، یک مهاجرت جبرانی رو‌به‌جلو اجرا شود؛ تاریخچه مهاجرت حذف یا بازنویسی نشود.
3. در صورت آسیب داده، نسخه پشتیبان دیتابیس در یک محیط جدا بازیابی و کنترل شود.
4. پس از کنترل شمارش‌ها و روابط، محیط بازیابی‌شده جایگزین شود.
5. ورود مدیر، ورود دانش‌آموز، شروع آزمون، ذخیره پاسخ و کارنامه دوباره آزمایش شوند.

## کنترل پس از بازیابی

- کد دانش‌آموزی تکراری وجود نداشته باشد.
- تلاش یا پاسخ یتیم وجود نداشته باشد.
- پاسخ صحیح برای کاربر ناشناس قابل دریافت نباشد.
- آزمون تحویل‌شده دوباره قابل ویرایش نباشد.
- رمزها و نشست‌های خصوصی از جدول‌های عمومی قابل خواندن نباشند.

## محدودیت

هیچ بازیابی مستقیم روی production بدون آزمون نسخه بازیابی‌شده انجام نمی‌شود. حذف داده، بازنویسی تاریخچه مهاجرت و استفاده از کلید `service_role` در مرورگر ممنوع است.
